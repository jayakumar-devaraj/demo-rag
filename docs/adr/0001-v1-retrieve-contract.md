# 0001 · `/v1/retrieve`: retrieval as a service, answer written by the caller

## Context

A second service (the chatbot) must answer questions from a tenant's documents. It has its own LLM
engine, streaming and output guards, so it needs the retrieved passages, not a finished answer. A user
is waiting, so the transport is synchronous HTTP, not a queue. Today only `/chat` exists and it always
runs synthesis.

## Decision

- `POST /v1/retrieve` runs the same retrieve → evaluate → re-query loop as `/chat`
  (`build_graph(..., retrieve_only=True)` ends at END on sufficient context instead of synthesizing).
  It returns `{sections, insufficient, queries_run, attempts}`. When `insufficient` is true,
  `sections` is empty, so a caller cannot answer from context the evaluator rejected.
- The tenant comes only from the bearer token; the request body has no tenant field.
- The contract is `docs/openapi-v1.json`, generated by `python -m src.routers.contract` and checked
  for drift by a unit test. `/v1` is additive; `/chat` and `/ingest` are unchanged.
- The caller owns retries. `/v1/retrieve` uses a second chat model whose provider-client
  `max_retries` is `RETRIEVE_LLM_MAX_RETRIES` (default 0); `/chat` keeps 2. The caller sends its
  deadline in `X-Timeout-Ms` (1 to 120000; default 30 s when absent); expiry returns 504.
- Status codes: 401 bad token, 422 bad input or header, 503 provider or database down, 504 model or
  deadline timeout, 500 anything else. Unlike `/chat`, a provider-client timeout
  (`APITimeoutError`) maps to 504, because the caller retries 503 and 504 on a different budget.

## Consequences

Worst-case provider HTTP requests per call, counted from the code (not measured): the loop makes at
most 3 evaluate calls; `/chat` adds 1 synthesis call, so 4 structured calls. Each structured call tries
the primary model then the fallback, and each client attempts 1 + `max_retries` times.

| Endpoint | Structured calls | Requests per call | Worst case |
|---|---|---|---|
| `/chat` (`max_retries=2`) | 4 | 3 + 3 | 24 |
| `/v1/retrieve` (`max_retries=0`) | 3 | 1 + 1 | 6 |

The caller's own retry count multiplies the `/v1/retrieve` figure. Evaluation still needs a chat
model, so `/v1/retrieve` returns 503 when none is configured. Sections are raw document text; the
caller is responsible for treating them as untrusted data.
