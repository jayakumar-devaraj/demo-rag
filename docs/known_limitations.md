- **Audit trail gaps (ADR 0002, step 2).** Rejected requests (401) are not audited, because no tenant is known to attach the row to; they are logged only. Any token of a tenant can read that tenant's whole trail (`GET /audit`), because static tokens have no scopes; scopes arrive with JWT validation. There is no `delete` endpoint yet, so the `delete` action is never written. Monthly partitioning and the retention job are not built. A whole-document ingest is now one transaction, so a very large upload holds its row locks until it finishes.
- **Row-level security (ADR 0002, step 3).** The tenant is bound per connection with a session-level setting, valid only while each request owns its connection (no pooling). Roles with BYPASSRLS or superuser, including the owner used by the migrate job and by the host-run `.env` default, are not confined, so only the compose `rag-api` service (app role) exercises the policies in normal use. JWT validation, monthly partitioning, the retention job and the 401 audit gap remain open.
- **JWT authentication (ADR 0002, step 4).** Static tokens are accepted by default until `ALLOW_STATIC_TOKENS=false`. Only a local JWKS endpoint was used in tests; no real OIDC provider was run. Keys are cached for 300 s, so a revoked signing key is trusted until the cache expires, and there is no per-token revocation list. Scopes gate the endpoints but `/audit` needs only `rag:query`, so any query token reads its tenant's whole trail.
